# Input Assistance Design: `lingo_help`

## User Intent

"I know what I want to say in my native language (L1), but I don't know the right expression in my target language (L2). Help me find the words."

This is the user's primary pain point: they WANT to type in L2, but get stuck mid-composition. The plugin should help them bridge the gap without switching to a translator.

## Trigger

**Explicit, user-initiated via natural language**. Examples:
- `@vibe-lingo help "我需要把返回值改成异步的"`
- `how do I say "我需要把返回值改成异步的" in English?`
- `@vibe-lingo help: implementar esta función como async`

The Agent interprets these as requests to call `lingo_help`. The tool is registered as `exposure: "resident"` so it's always available.

               │
               ▼

│   query: "我需要把返回值改成异步的",                           │

## SLA Foundation

### Output Hypothesis (Swain, 1985, 1995)
The user's attempt to produce L2 output is central to acquisition. When they get stuck, they are experiencing Swain's "noticing the gap" — awareness of what they can't yet express. `lingo_help` bridges that gap while preserving the user's communicative intent. The assistance enables output that would otherwise be impossible.

### Comprehensible Input (Krashen, 1985)
The expressions generated by `lingo_help` serve as additional comprehensible input. By providing 2-3 alternatives at slightly different complexity levels, the user can choose the expression that matches their current i+1 level.

### Involvement Load Hypothesis (Hulstijn & Laufer, 2001)
The user's act of formulating an idea in L1 then seeking the L2 equivalent involves high Need (must express this idea), Search (actively seeking the expression), and Evaluation (choosing between alternatives). This maximizes vocabulary retention.

### Zone of Proximal Development (Vygotsky, adapted for SLA)
The plugin provides scaffolding that lets the user produce output at a level slightly above their independent ability. As proficiency increases, the scaffolding recedes.

## Design Decisions

### Why 2-3 Alternatives?

One translation creates dependency. Multiple alternatives force the user to evaluate and choose — which boosts involvement and retention. "Which one sounds more natural for my situation?" is a productive linguistic evaluation.

### Why Structure Notes, Not Grammar Lectures?

The user is mid-task (coding, researching). A grammar lecture about Chinese-English syntactic differences is disruptive. A brief vocabulary mapping note ("返回值 = return value") is actionable and learnable in 3 seconds.

### Why Not Full Translation?

The user didn't ask for a translator — they asked for HELP expressing themselves in L2. A single translation ("I need to make the return value asynchronous") is a recast. Multiple expressions with minimal explanation is closer to metalinguistic feedback (evidence: prompts d=0.83 > recasts d=0.53).

## Edge Cases

| Edge Case | Handling |
|-----------|----------|
| Query mixes L1 and L2 (code-switching) | Auto-detect. If >50% is L2, treat as "polish" not "help." Prompt user to clarify. |
| Ambiguous query (multiple valid interpretations) | Present alternatives for each interpretation. Flag ambiguity. "If you meant X, use A. If you meant Y, use B." |
| Query is domain-specific jargon (coding terms) | Preserve technical accuracy. Never "simplify" technical terms into generic equivalents. "Race condition" stays "race condition." |
| Query contains code snippets | Detect code blocks. Treat code as untranslated. Only translate natural language portions. |
| Target language not set | Prompt user to set target language on first use. Store preference in Memory. |

## Interface Contract

### Input
```ts
interface LingoHelpInput {
  query: string          // What the user wants to express (in any language)
  context_hint?: string  // Optional: what they're trying to do (coding, writing, etc.)
  register?: "formal" | "casual" | "technical"  // Desired tone
}
```

### Output
```ts
interface LingoHelpOutput {
  expressions: Array<{
    text: string                     // The expression in target language
    notes?: string                   // Brief explanation of key vocabulary/structure
  }>
  detected_source_lang?: string      // Auto-detected source language
  target_lang: string                // Target language
}
```
